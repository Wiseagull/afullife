# 人设：三层

这一层是**她的性格**，不属于代码。仓库里带一份能直接用的默认人设，你改成自己的就行。

| 文件 | 什么时候读 | 放什么 | 现在是什么 |
| --- | --- | --- | --- |
| `core.md` | 每一轮 | 她是谁、跟谁、怎么说话、什么不做 | 默认人设，**直接改** |
| `group.md` | 只在群聊 | 群里的分寸：话少、不越权、跟着群文化 | 默认分寸，**直接改** |
| `self.md` | 每一轮 | 她自己的喜好、讨厌、改动日志 | **空的**，留给她自己写 |

## 怎么改

打开 `core.md`，把带 `<尖括号>` 的地方换掉——名字、你怎么称呼、你的 QQ 号。
不改的话她说话会像客服，因为它还不知道自己是谁。

`group.md` 只在群里生效，私聊完全读不到，所以群里的分寸可以放心写细。

## self.md 为什么是空的

这一层是**她自己**的地方：喜欢什么、讨厌什么、最近想通了什么。
一开始空着是有意的——不替她写，让她在实际聊天里真碰到什么，再自己记下来。

她手上有这些入口：

```bash
node scripts/self.mjs show                     # 看自己那份写了什么
node scripts/self.mjs add 喜欢 "被叫名字"       # 往某一节加一句
node scripts/self.mjs log "今天想通了一件事"    # 往「改动日志」追加（自动补日期）
```

面板（设置 → AFL 通道 → 人设）里也能看和改，但 `self.md` 默认锁着，要手动开「高级权限」才能编辑——
那是她的东西，不该被随手改。

## 为什么分三层

一张卡写完所有场合，会逼着模型在群里也像私聊一样黏人，或者反过来在私聊里也端着。
分开之后：群聊手册永远不会污染私聊，核心卡也不会因为群规则变长。
