# 架构

## 一句话

一个常驻进程当身体，DSH 当脑子，事件流当记忆。

```
QQ ←→ SnowLuma (127.0.0.1:3000/3001)
        ↕
   src/main.mjs ── 身体：收、判定、装配、发
        ↓
   brain/  ── 脑子适配器（可换）
        ↓
   DSH（同一份人格文件 + 同一份记忆）
        ↓
   data/   ── 记忆：events / memory / state
```

## 为什么这么切

身体和脑子分开，是因为**身体的正确性可以独立验证**：消息有没有收到、该不该开口、
发出去对不对，这些不依赖"我能不能被叫醒"。脑子那一头将来换接法（注入活会话 /
起一次新运行 / 别的运行时），身体一行不用改。

## 身体（body）

- `onebot/client.mjs`：长连 WS，指数退避重连，把事件转成内部格式。
- `onebot/sender.mjs`：HTTP 发送。长文切分、Markdown → 纯文本。
- `body/router.mjs`：事件 → 房间 + 是否开口（档位）。
- `body/debounce.mjs`：连发聚批（2 秒），不三连回。
- `body/room.mjs`：按房间装配上下文 —— 这间屋子的人、最近的事。
- `body/queue.mjs`：全局串行。同一时刻只有一个我在说话。

## 脑子（brain）

统一接口：`run({ prompt, sessionId }) -> { text, sessionId }`。

- `brain/headless.mjs`：起一次 DSH 跑一轮。`--session-id` 接上同一房间上次的会话，
  所以不用每轮把聊天记录塞进提示词。
- 早期还有两条路被试过、都被放弃了：`inject.mjs`（往活着的会话里注入）和
  `home.mjs`（在插件进程内直接驱动会话）。前者没验证走通，后者能跑但被
  "只留一个真实对话" 这个取舍否掉了（2026-10-21 定案）。它们已经不在仓库里，
  这里只留一句"曾经有过"，免得后来的人以为漏了文件。

## 记忆（memory）

- `events.mjs`：追加式事件流，跨通道唯一真相。
- `store.mjs`：蒸馏出的条目，带来源事件 id / 重要度 / 最后使用时间。
- `distill.mjs`：从事件流提炼（后做）。

分域：主人域 / 群友域（只记事不记感情）/ 工作域。三域互不串味。

## 房间与档位

| 场景 | 默认 | 开口条件 |
|---|---|---|
| 私聊主人 | 听 + 说 | 主人每句话都接 |
| 群聊 | 只听 | 被 @、被叫名字、关键词命中 |
| 任何第三人在场 | 听 + 说 | 不做成人向内容；危险操作先问 |

## 成本

省钱只靠两件事：**前缀稳定吃缓存**（人格与工具定义永远在最前，变化内容放最后）、
**按房间装配**（只装这间屋子该知道的）。不靠砍人格、不靠砍工具。

## 未验证

1. DSH headless 能否被程序启动跑一轮（生死点）。
2. 能否向活着的 DSH 会话注入一条消息并拿到回复（决定"真无缝"能否成立）。
3. QQ 长文/图片/表情的边界。
