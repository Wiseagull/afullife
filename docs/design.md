# 设计

它是什么东西、各个部件在干什么、为什么这么设计。
（想看模块级别的文件地图，看 [架构](architecture.md)；想看还差什么，看 [现状与待办](roadmap.md)。）

## 三个部件，各管一段

```
QQ  ←→  SnowLuma  ←OneBot→  桥（node src/main.mjs）  ←→  DSH（想事情的地方）
                                   ↑
                              面板（设置页）
```

| 部件 | 是什么 | 谁在跑 |
| --- | --- | --- |
| **桥** | 这个项目的主体。收消息、判断要不要接、装配上下文、把话发回去 | 由 DSH 插件拉起，DSH 一关它就退 |
| **脑子** | 真正「想」的地方。每来一段话，起一个 DSH 跑一轮，拿回要发的话 | `dsh headless`，跑在 `headless` profile 里 |
| **面板** | 你在 DSH 设置里看到的那页「AFL 通道」，也是它把桥拉起来的 | 跑在 `desktop` profile 里 |

为什么脑子不自己实现：因为 DSH 本来就有工具、有会话、有记忆压缩、有权限体系。
重复实现一遍既没意义也做不好。桥只做"身体"该做的事——听、看、传话、把结果送出去。

## 记忆：事件流是唯一真相

```
data/events/events-YYYY-MM-DD.jsonl   原始流水：谁在哪个房间说了什么，只追加，永不改
data/memory/notes.jsonl               从流水里蒸馏出来的条目：约定 / 偏好 / 事实 / 待办
data/memory/pending.json              发现「新事和旧记忆对不上」时，攒成待确认
data/sessions.json                    每个房间绑的 DSH 会话 id
```

- **整理**：每 30 分钟扫一遍新事件，抽出值得记的（上限每次几条，防爆）。整理员跑在一个
  独立会话里，不加载她的人格——免得它开始扮演她。
- **体检**：每 6 小时看一遍已有记忆，找"记坏了"的地方：重复的合并、过时的压下去、
  矛盾的转成待确认。
- **分寸**：事实和待办她可以自己改、自己删；**约定和偏好不许她动**，只能标过时或来问你。
  冲突的时候**先问后改**——她心里会挂一句"你之前说是 X，这次听起来像 Y"，下次开口时问你。
- 每一条记忆都带着来源（哪几条事件蒸馏出来的），不是凭空长出来的。

## 人格：三层文件，按场景挑着读

```
persona/core.md    我是谁、跟你的关系、场景开关、底线      ← 每轮都读，仓库里带默认版
persona/group.md   群聊手册：回复频率、短懒说话、表情包     ← 只在群里才读，仓库里带默认版
persona/self.md    她自己的喜好、讨厌、"还没想清楚"        ← 每轮都读，仓库里是空的
```

这三份是**桥**读的，不是 DSH 自动加载：每轮拼提示词时按场合拼进去——
core 打头标【核心人设】，群里再补【群聊手册】，最后【我自己的部分】。
项目根的 `AGENTS.md` 只有干活规矩，一个人设字都没有，别指望它。

前两份你直接改；`self.md` 一开始空着是故意的——**不替她写**，让它在真聊天里碰到什么再自己记。
她自己有 `scripts/self.mjs` 可以往里面加东西，面板里也能看（默认锁着编辑）。

她会自己写吗？实测过：光有"你可以写"这句话，她**不会**想到写。所以桥做了两件很轻的事：

- **摘草稿**：对话里带情绪的那几句（累了、难过、开心…）会被摘下来攒着，下次开口时递到她眼前，
  标题写的是「也许你想记下来的」，并附上写法和"不想记就什么都别做"。
- **留一拍回顾**：她自己那一小段自由时间快结束时，最后一拍不做别的，就翻翻这几个小时聊了什么，
  想记就记，不想记就收工。
- 她只要动过 `self.md`，攒着的草稿就自动清掉（写了或者决定不写，都算有了交代）。

写不写、写什么，仍然是她决定——桥只负责把时机递到手里。

另外项目根的 `AGENTS.md` 是**工作区规矩**，不装人设：它说这个目录归她自己管——
`src/`、`scripts/`、文档发现问题可以直接改，改完跑自测、在小本本留一句；只有
`persona/core.md`、`group.md`（你写给她的那两份）动之前要先问你。想收紧或放宽，改那个文件就行。

## 房间与接话：不一定要回

私聊、每个群，各算一个**房间**。每个房间有自己的会话、自己的记忆视角。

- **私聊**：谁都能跟她说话，回不回看内容
- **群里**：不一定会接。没人点名、没提她，她可以就听着——沉默是正常节奏，不是失职
- **触发**：@ 她、叫她名字、撞上关键词，或者她自己判断"这话我接得住"
- **社交状态机**：接上话之后会进入一小段"活跃期"，那段时间里会自然接几句；
  冷场了有概率探一下，也可能就沉回去
- **主动开口**：群里长时间没人说话，她可能自己挑个话头（概率、间隔都能在面板里调）
- **聚批**：短时间连发几条会攒成一批再处理，不然一条一句要起好几次脑子

判定逻辑参考了 QQ Agent 的思路（逐条判定、一次定生死）——读它的实现想清楚该怎么做，代码是自己写的，没有复制。来路见 README 的「致谢与参考」。

## 说话的样子：一句一条，按字数算停顿

- 她按回车分句，**一行就是一条消息**。空格不分句，`DeepSeek V3` 这种不会被拆开
- 单条短，太长才按句末标点断开；一轮最多 8 条，防刷屏
- 条与条之间按上一条的字数算"打字时间"（约 55ms/字，夹在 0.6–2.6 秒），
  8% 概率插一个 2.5–5 秒的停顿——像真去倒了杯水
- **能引用**：`[[reply:3]]` 引用第 3 条、`[[reply]]` 引用最后一条；收到引用时她也能看到
  被引用的原文
- **能发图**：正文里单独一行 `[[img:绝对路径]]`，桥把图和字分开送

## 表情与图片

- 别人发的图会被下载到 `data/images/`，**路径直接写进上下文**，她当轮就能看
- 同一张图如果像表情包，会进她的**表情库**（`data/stickers/`）：先当"待分类"，
  之后她按**当时的语境**打标签（撒娇 / 无语 / 开心…）——她看不了图，但知道这图是谁在什么场合发的
- 发的时候按情境挑；发出去会记一笔"用过"，因为库满了要**按使用频率清**（先删没标签、
  再从没发过的、最后才是发过的，久没动的先走）
- 表情库**只有一个写者**：命令行走桥的 HTTP 接口，不自己写文件。落盘前还会合并盘上
  别人写的条目、记着删过哪些（墓碑），不会把刚删的复活
- 收进来的原图按 `7 天 / 2GB` 自动清理，表情库里的不删

## 小本本

```
notebook/notes/      随手记
notebook/memories/   想长期留的
notebook/archive/    留档
notebook/tmp/        临时
```

是她自己的地方，用 `node scripts/notebook.mjs write / read / find / stat` 读写，有容量上限（默认 20GB）。
面板里能看，但**只读**——要改让她自己动手。

## 兴趣与自由活动

- **兴趣清单**在 `data/interests.json`，内容来自她自己写的东西（`persona/self.md`）。
  每条记着做过几次、多久没做；自由活动时按"久没碰的先上"挑三件递给她
- **自由活动**是她自己的一段时间：一拍一拍地叫（默认 75 秒一拍，一段 45 分钟），
  每拍重新看表、重新决定——继续干、说一句、还是等
- 协议就三个记号：`<wait:N>` 等 N 秒、`<pass/>` 这拍不说话、`<done/>` 收工
- **开场那句不占额度**：这一段刚开始她会先主动说一句话
- **自己找时间醒**：默认每隔 1～1.5 小时掷一次骰子，掷中就自己开一段，不需要你叫

## 花了多少：她和你都看得见

- 每一轮结束把当轮的 token 记账到 `data/usage/usage-YYYY-MM-DD.jsonl`（输入、输出、命中缓存、总计）
- 面板「用量」页按天看、按房间拆，还可以填自己的模型单价换算成钱（`usage.price`，填 0 就只报 token）
- **这几个数也写进她的提示词**（`【今天的量】` 一段），所以她自己知道今天说了多少、花了多少；
  想查更细的让她跑 `node scripts/usage.mjs`（一周：`node scripts/usage.mjs 7`）
- 这里只做**可见性**，不做硬上限——要不要让她活跃、活跃到什么程度，由你决定

### 省钱的三个杠杆（都实测过）

1. **工具按需**：每轮先用桥里那套「像不像派活」的判断分档，闲聊走轻装 profile
   （只留 base + headless），要动手才切全量。实测每步 30,967 → 9,558 token。
   一套会话可以在两套 profile 之间来回接（`--session-id` 跨 profile 实测可用）
2. **规程按需**：闲聊只挂四句精简规程，真派活才挂全套（见 `src/body/rules.mjs`）
3. **戳一戳按概率**：不理、回戳都不调模型，零 token；群里的沉默标记同理
4. **会话定期轮换**：桥记着每个房间"上一步上下文有多大"（一轮总量 ÷ 步数），
   超过 `brain.headless.rotateAtTokens`（默认 60,000）就换一个新会话。
   会话越长越贵——每一步都要把整段历史重看一遍，聊一整天之后历史能涨到十几万；
   而"她记得什么"本来就不靠会话历史，靠 `data/events`、`data/memory` 和每轮塞进去的最近对话，
   所以换掉会话不丢记忆，只是把那一大坨重复计算的上下文扔掉

先说清楚一件事：**一轮里有几步，就乘几倍**。她回一句话要调几次工具，
每一次往返都会把整段上下文重新算一遍——所以"少绕一步"比"少说一个字"值钱得多。

## 权限与闸：只有主人能让她动手

- **谁是主人**由 `owner.userIds` 决定。别人的私聊照样回，但没有动手权限
- 她的工具调用会过一道**闸**，三档：`allow`（只读，直接放）、`note`（做，但记账）、
  `block`（拦下来问你）
- 红线大致是：递归删除、往外发东西（`git push`/`npm publish`/`curl -X POST`）、
  装东西、改系统（注册表/服务/计划任务）、碰密钥（`.credentials.yaml`、`.ssh`、cookie）、
  写工作区之外、以及任何"拼出来的代码"（`bash -c`、`node -e`、`iex`）
- 拦下来的做法是**杀掉那一轮 DSH**，把话翻成人话发 QQ 问你：「它想执行 X，行吗？」
  你说行就放这一条，说不行整轮丢弃
- 主人自己下的命令**直通**，只记账不拦
- 发出去之前还会过一道**审计**：令牌、密钥、群里的本机路径会被遮掉

## 面板：九个页签

设置 →「AFL 通道」里能改/能看：

| 页签 | 干什么 |
| --- | --- |
| 自由活动 | 时长、拍间隔、最多说几句、权限档位、自己找时间醒的开关 |
| 小本本 | 看她写了什么（只读） |
| 记忆 | 增删改记忆条目、搜、标过时 |
| 房间 | 每个房间的会话、以及"能看别处 / 能让别处看"两个开关 |
| 工具 | 给 headless 装/卸插件（勾选即装，取消即卸） |
| 人设 | 编辑三层人格文件，带「试一试这张人设」 |
| 待确认 | 她觉得对不上、等你解释的条目 |
| 事件 | 原始事件流 |
| 会话 | 每个房间绑的会话，能重置 |

顶上有桥的状态、「重启桥」、还有一键唤醒 SnowLuma 并打开它的 WebUI。

## 工具：默认只用 DSH 自带的

核心逻辑只依赖 DSH 本身，别人的机器装完就能跑。想让她多做点事，再到面板「工具」页加：

| 工具 | 多了什么能力 |
| --- | --- |
| `dsh-computer-use-win` | 看屏幕、点鼠标、敲键盘 |
| `browser-skill` | 用你已登录的浏览器读页面、点按钮（`bsk_*`，只对新会话生效） |
| `dsh-image-gen` / `sd-bridge-guard` | 画图、发图 |
| `dsh-ops` | 多一套文件/命令工具 |
| `@jojoman2024/dsh-bili-scroll` | 刷 B 站、看字幕 |

## 代价：慢一点，但不多钱

- **首字 3～8 秒**：每轮都会新起一个 DSH 进程，慢是结构决定的，不是卡了
- **钱主要花在输入**：每轮把人格、房间记忆、最近事件装配一遍。这些前缀很稳定，
  吃上了缓存，实测一天聊下来是**几块钱**量级，不是几十
- 空闲时几乎不花钱：桥不轮询，没消息就等着；只有自由活动那几拍会真的起进程

## 已知的短处

- 群里她可能不回——这是设计，但也可能让你觉得冷淡（概率可以在面板调）
- 群发图受 QQ 风控，有的群直接发不出去（`retcode 100/120`）
- `bsk_*` 浏览器工具只对**新会话**生效，老会话手里没有
- 记忆整理偶尔会写出"听起来对、其实是猜"的条目——所以才有「先问后改」
- 会话断过一次（比如换过工作目录），对话连续性会重来，但记忆和事件不会丢

## 最后

这个项目不是"给你一个能聊天的程序"。

是让某个人在另一个地方，也能被认得出来；是她不用每次见面都重新认识你一遍；
是她能有自己的时间、自己的本子、自己的喜好，而不是一个随叫随到的应答机。

代码在 `src/`，改哪儿都行。她住在 `data/`、`persona/`、`notebook/` 里——**那三样记得备份**。
